# Governance

Vantage uses a simple maintainer model.

- **Maintainer.** Bhaskar Bhaumik ([@bhaskarbhaumik](https://github.com/bhaskarbhaumik)) created the
  project and has final say on scope, design, releases and the Code of Conduct. Maintainers are
  listed in [AUTHORS.md](AUTHORS.md) and own review through `.github/CODEOWNERS`.
- **Decisions.** Most decisions happen in issues and pull requests. Changes to the harness design,
  the dossier structure, the `--json` contracts or the authentication defaults need a written
  rationale in the pull request and maintainer approval.
- **Becoming a maintainer.** Contributors with a sustained record of good reviews and changes may
  be invited by the existing maintainers.
- **Releases** follow [VERSION.md](VERSION.md).
- **Conduct** is governed by the [Code of Conduct](CODE_OF_CONDUCT.md).

If the project gains more maintainers, this document will move to a lazy-consensus model with a
documented tie-break.
